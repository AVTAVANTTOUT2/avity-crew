# Claude Code adapter

`ClaudeProvider(binary = 'claude')` uses the installed CLI and its native authentication. No API key is copied or required by Avity Crew. The protocol fixture and live matrix target Claude Code 2.1.304. Other versions remain `unverified` even when their local help advertises the required options.

Prompts travel on stdin. The adapter uses print mode with `stream-json` and `--verbose`, captures the exact `session_id`, and resumes only that UUID. A resumed turn receives its new team context in the prompt; changing the original system prompt is not assumed to replace the session's stored instructions. Models come from `ProviderRequest.model` or the native default.

Read-only requests expose the built-in Read, Glob and Grep tools. Workspace requests use native `acceptEdits`. No global Bash permission or permission bypass is added. Unattended permission prompts are denied and normalized as explicit permission/error events; the supervisor decides how to wait, ask and resume. A read-only request for a missing tool may instead receive a normal explanatory answer: successful provider completion alone does not establish that the requested task was performed. Claude's native tool permissions are not a new operating-system sandbox. MCP tools require their own role/workspace authorization in the supervisor bridge.

The bridge is named `crew`, supplied only through the session's strict MCP configuration. Its environment values enter the CLI process environment and are referenced by name in the MCP config. No values are copied to argv, prompts or diagnostics. Existing global MCP servers are not added to the team's tools. Native authentication is retained; `--bare` is deliberately absent.

`bridge.approved_tools` lets the supervisor supply native consent after applying the bridge's transport ACL. When omitted, the existing `mcp__crew__*` consent remains for compatibility with the L04 bridge recipe. When present, only its canonical `ToolCall` method names become explicit `--allowedTools mcp__crew__<method>` entries; an empty list adds no consent. Duplicate names, unknown methods, server-qualified names, wildcard patterns and injected rule fragments fail with `INVALID_INPUT` before spawning. This list cannot expand the transport ACL or override a native deny rule. It does not change the run's sandbox or global approval policy, and mutating tools must retain truthful `readOnlyHint: false` annotations. Native permission denials remain fatal even for a listed method.

This policy is checked with offline argv and denial fixtures against Claude Code 2.1.304 local help (`--allowedTools <tools...>`) and the official [CLI reference](https://code.claude.com/docs/en/cli-reference) and [permission precedence](https://code.claude.com/docs/en/permissions). Actual mutating `create_task`/`publish_note` calls require the L07 integration recipe; the earlier read-only ping recipe is not evidence that those mutations were executed.

The shared runner parses fragmented UTF-8 JSONL, bounds each line to 1 MiB and response text to 2 MiB, and applies backpressure after 128 queued events. Consume `events` concurrently with `result`. Unknown events and stderr remain explicit, redacted diagnostics (16 KiB maximum per diagnostic, with a truncation marker). Invalid or oversized protocol output fails the turn. Final success requires a native successful terminal result, process exit 0, no error and no interruption. `rate_limit_event` alone is a diagnostic, not a failure.

Mid-turn `send()` is unsupported and raises `UNSUPPORTED`; the supervisor queues updates for the next exact resume. On POSIX, interrupt/stop signal the spawned process group and escalate to SIGKILL, including children surviving their parent. On Windows only the direct child is currently stopped; process-tree support is unverified there. Closing the event consumer stops an unfinished child.

Offline verification: `npm run build`, then `node --test dist/tests/providers/process.test.js dist/tests/providers/claude.test.js`. These tests use simulated protocol/process fixtures, not paid provider sessions.

Explicit live verification, after building: `node scripts/live-claude.mjs /absolute/path/to/claude-live-report.json`. This consumes the user's configured native provider resources. It runs a real file edit, MCP ping, exact resume with a new note, an independent session, a read-only tool-boundary check, a controlled native denial and interruption in a disposable directory. The controlled denial calls the same runner/decoder with restricted native settings so the user's existing allow rules cannot silently approve the probe. The report distinguishes that control case from normal adapter operation. The script deletes its disposable workspace and writes sanitized evidence; L04 acceptance uses the canonical workpack's validation report. Same-provider live concurrency is a separate coordinated verification, not claimed by this sequential script.
