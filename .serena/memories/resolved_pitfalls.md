- Context tool metadata is projected to `{name, description}` before serialization. Native tool schemas are already supplied by the provider; duplicating full descriptors in the mandatory mission can exhaust its budget without adding useful context.
- Preserve `required_source:ID` when an applicable AGENTS instruction is selected. Source IDs are qualified by workspace; the required original ID must resolve through the recorded replacement, retaining content hashes and changed-source observations.
- A recovered workspace may start at a partial snapshot, but its final Git delivery remains cumulative from `TaskSpec.base_revision`. Validate the complete diff against scope/exclusions and require that task baseline to be an ancestor of the workspace baseline. An incompatible amended base needs explicit reassignment, not a silent rebase.
- Claim the recovery attempt and consume its delegation before the fallible snapshot await. Preparation failure then records an exited attempt without a PID and blocks that task instead of automatically retrying the same queued delegation. Old files remain preserved; uncertain content is not claimed to have been imported automatically.
- `finish_run.criterion_evidence` uses IDs actually listed in retained passed `Verification.evidence_artifact_ids` for that criterion. A manifest or Git commit can be a valid delivered artifact without being a proof artifact. Current linked control results may prove review criteria; obsolete review results cannot. Inspect status/verification records rather than inventing IDs.
- Revalidate authenticated agent authority at dequeue and before asynchronous effects publish proofs or advance a Git reference. Do not add a naive post-transition check that rejects a legitimate `submit_review` or `finish_run` after it revokes its own authority.
- Terminal cell width: only Emoji_Presentation/VS16 and East Asian scripts are 2 columns (`cellWidth`). Counting all Extended_Pictographic (⚠, ✔) as wide shifts borders in real terminals.
- Worktrees are fresh checkouts without dependencies: project `workspace_setup` runs in every new agent and candidate worktree; setup proofs stay in `candidate.setup`, never as criterion Verifications.
- Integration candidates are deterministic (cherry-pick committer = fixed identity + snapshot commit date): re-running propose_integration with a new key rebuilds the same SHA in a new worktree, so reviews of that SHA stay valid. accept_delivery must pick a `validated` preparation of the revision, not the first one.
- Agent-facing get_status must stay under native MCP output limits (~40k chars): event payload strings are clipped and pages carry next_seq/has_more. Admin status/export keep full events in size-bounded pages; CLI JSON export gathers all pages.
- Recovery snapshots the task's latest code workspace (not only the active attempt's), so unsubmitted work survives an attempt that never got a worktree or an explicit reassign; after reassign, BASE_CHANGED falls back to the amended base (`recovery.skipped`).
- Engine mutation events carry only `{request_key, subject_id}`; message/handoff/blocker content must come from records (get_status messages, export handoffs/reviews), never be inferred from the event.
- Reconnection fixtures must observe the initial successful snapshot before closing a server. Fixed startup sleeps can miss the intended disconnect under parallel test load.
- A handoff's `limitations` blocks acceptance; personal checks intentionally not run belong in `next_information` when observed supervisor checks cover the criterion. Validate all handoffs before accepting any part of a combined batch: accepted tasks are terminal. A blocked review requires producer resubmission before a fresh review; a closed control task needs a new control task, while an unfinished blocked control task can be amended/redelegated.
